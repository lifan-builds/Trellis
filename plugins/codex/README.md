# Trellis Codex plugin

This companion plugin registers Trellis's Codex hook entry points once, so a
Codex user can review the plugin hook definitions instead of approving an
equivalent project hook in every repository.

## Install

Install the `plugins/codex` directory from the Trellis repository with the
Codex plugin manager, then enable the **Trellis** plugin. The plugin directory
contains the `.codex-plugin/plugin.json` manifest and does not need to be
copied into a project.

In each project, run the normal setup when Trellis is not initialized yet:

```sh
trellis init --codex
```

The plugin is currently intended for Codex App/CLI surfaces that support
plugins. Codex IDE integrations without plugin support continue using the
project-local hooks generated by `trellis init --codex`.

## What it does

The plugin registers `UserPromptSubmit` and `SubagentStart` hooks. Its small
dispatcher finds the nearest repository containing `.trellis/` and forwards
the original Codex event to the corresponding hook generated in
`.codex/hooks/`. It exits quietly for non-Trellis repositories and for
repositories that have not generated the local Codex hook yet.

Trellis state, specs, skills, agent profiles, and hook implementations remain
project-local. Installing the plugin does not copy or replace any of them.

## Trust and permissions

Plugin hook review is still required when the plugin is installed or enabled.
The benefit is that the stable plugin hook definition can be reviewed once;
changing that definition may require review again. Plugin approval is separate
from command/tool approval, sandbox permissions, and access to external
services.

The existing `.codex/hooks.json` integration remains a supported fallback, so
projects can use Trellis without the plugin and can remove or disable it
without losing their local workflow hooks.

This is an initial companion-plugin proposal tracked in
[Trellis issue #593](https://github.com/mindfold-ai/Trellis/issues/593).
